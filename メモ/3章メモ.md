# 第3章：各種生成AIの特徴・仕組み・活用

---

## 1. 生成AIの種類と特徴

生成AIには「何を生成するか」によってさまざまな種類がある。

### テキスト生成AI
- **自然言語処理（NLP）** と機械学習の技術を使って、文章・テキストデータを自律的に生成する技術
- **NLP（Natural Language Processing）**＝コンピュータに人間の言葉を理解させるための技術
  - 活用例：翻訳ソフト、スマートスピーカー（話しかけた内容を理解して返答）
- 非常に大規模なデータセットで学習された自然言語処理モデル＝**LLM（大規模言語モデル）**がこれに該当
- 代表例：**ChatGPT**（OpenAI）、**Claude**（Anthropic）、**Gemini**（Google）など

### 画像生成AI
- コンピュータが画像を生成するための技術

**学習〜生成の流れ：**
1. インターネット上の大量の画像データを収集
2. **前処理**してモデルに適した形式に変換
3. 生成モデルで高品質な画像を生成

**前処理の3つの操作：**

| 操作 | 意味 | 目的 |
|------|------|------|
| **リサイズ** | 画像の縦横ピクセル数を統一する（例：全画像を256×256に揃える） | AIは入力サイズが固定のため、バラバラなサイズを統一する必要がある |
| **正規化** | 画像の各ピクセルの値（0〜255）を0〜1や-1〜1の小さな数値に変換する | 数値が大きすぎると計算が不安定になるため、スケールを揃えて学習を安定させる |
| **データ拡張（水増し）** | 1枚の画像を反転・回転・色調変更などして複数の画像を作る | 学習データが少ないと過学習しやすいため、人工的にデータを増やして汎用性を高める |

**主な生成手法（現在も全て使われている。目的に応じて使い分ける）：**

> ⚠️ 以下は「廃れた→次へ」ではなく、**それぞれ得意な用途があり現在も並行して使われている**。
> 歴史の流れとして登場順に理解すると覚えやすい。

---

**① GAN（敵対的生成ネットワーク）**

- 生成器（偽造師）と識別器（鑑定士）を競わせて学習する手法
- 用途：リアルな顔写真・アート画像の生成、画像の高解像度化など

**学習が不安定になりやすい理由：**
```
生成器と識別器のバランスが崩れると学習が破綻する。

例：識別器が強くなりすぎると
　→ 生成器がどんな画像を作っても「偽物」と判定され続ける
　→ 生成器は何を改善すればいいか手がかりが得られず学習が止まる（モード崩壊）

逆に生成器が強くなりすぎると
　→ 識別器が騙されっぱなしになり、品質チェックが機能しなくなる

この「2つのネットワークのバランス調整が難しい」ことが不安定さの原因。
```

---

**② VAE（変分自己符号化器）**

- エンコーダで画像を「潜在ベクトル（情報を圧縮した数値の塊）」に変換し、デコーダで復元する手法
- 用途：データ圧縮・異常検知・新しい画像の生成など

**生成画像がぼやけやすい理由：**
```
VAEの学習目標は「元の画像を正確に復元すること」。

復元の誤差を最小化するため、AIは
「どの画像にも当てはまる無難な平均的な見た目」を選びやすくなる。

例：犬の画像を大量に学習すると
　→ 「ゴールデンとシェパードのどちらの特徴もある曖昧な犬」が生成される
　→ 結果としてぼんやりした画像になる

GANは「識別器を騙す＝鮮明に見せる」という競争があるためシャープになるが、
VAEにはその競争がないためぼやけが生じやすい。
```

---

**③ ディフュージョンモデル（拡散モデル）← 現在の主流**

**まず「拡散」とは？**
物理現象の「インクが水に広がっていく」イメージ。
きれいな画像が少しずつノイズ（ランダムな点）で汚れて、最終的に完全なランダムノイズになる現象を「拡散」と呼ぶ。

**ディフュージョンモデルがやること：**
```
【学習フェーズ】
きれいな画像
　↓ ノイズを少しずつ加える（何百ステップもかけて）
　↓ ノイズを少しずつ加える
　↓ ノイズを少しずつ加える
完全なランダムノイズ

この「どのステップでどれくらいノイズが加わるか」をAIに覚えさせる。
= 「逆算すれば元に戻せる」ことを学習している。

【生成フェーズ】
完全なランダムノイズ（スタート地点）
　↓ 学習した逆操作で少しずつノイズを除去
　↓ 少しずつノイズを除去
　↓ 少しずつノイズを除去
きれいな新しい画像（完成）
```

**なぜGAN・VAEより優れているか：**
- GANのような「2つのネットワークの綱引き」がない → **学習が安定する**
- VAEのような「平均的な画像」ではなく、ステップを細かく踏むことで **高精細な画像が生成できる**
- 代表例：**Stable Diffusion・DALL-E・Midjourney**

---

**④ 自己回帰型Transformer**

- 画像をトークン（小さなブロック）に分割して左上から順次生成する手法
- Transformerの「文章を1単語ずつ生成する」能力を画像に応用したもの
- 看板の文字・細い線など**細部も破綻なく表現可能**
- 用途：テキスト埋め込みが必要な画像・高精度な細部表現が求められる場面


### 音楽生成AI
- コンピュータが音楽を作り出すための技術

**MIDIファイルとは？**
音楽の「楽譜データ」をデジタル化したファイル形式。
実際の音声ではなく「どの音を・いつ・どの強さで・どの長さで鳴らすか」という**演奏指示の情報**が入っている。
例：「ドを0.5秒、強さ80で鳴らせ」という命令の集まり。ファイルが軽く、楽器を自由に変えられるのが特徴。

**「データを水増し」とは？（データ拡張）**
学習データが少ないと過学習してしまうため、既存の曲データを加工して疑似的にデータを増やすこと。
例：テンポを少し変える・音程を半音上げる・楽器を変える → 同じ曲でも別の学習データとして使える。
**RNN**を使ってシーケンスデータ（時系列の音符の並び）を水増し・生成する。

- 人間のリスナーからフィードバックをもらい、そのデータをデータセットに追加 → より好まれる音楽を生成する能力を向上させていく

### 音声生成AI（TTS）
- コンピュータが音声を生成するための技術
- 大量の音声データを使ってディープラーニングモデルを学習

**なぜ教師あり学習を使うか？**
音声生成AIは「このテキストを読むとこういう音声になる」という**正解ペア**が明確に作れる。
例：「おはようございます」というテキスト ＋ それをナレーターが読んだ音声ファイル → 正解ペア完成。
「テキスト（入力）→ 正解の音声（出力）」のペアを大量に与えることで学習できるため、**教師あり学習が最適**。
正解データが用意できる＝教師あり学習、という原則通り。

| サービス | 特徴 |
|------|------|
| **OpenAI TTS**（Text-to-Speech） | テキストを自然な音声に変換。多言語・話者感情表現に対応。読み上げ・ナレーションに利用 |
| **ElevenLabs** | 少量のサンプルから声色を再現できる高品質TTS。感情・話速の制御、多言語合成に対応。配信・制作現場に広く利用 |

- 近年は**リップシンク技術**（特定人物の口の動きを音声に合わせて動かす）も進化し、エンタメからビジネスまで広く普及

### 動画生成AI
- コンピュータが静止画像を連続的に結合して動画を作成する技術
- 大量の動画データを収集し、フレームごとに分割して学習

**GAN・VAE・RNNがどのように使われるか：**

動画は「静止画（フレーム）の連続」。生成には2つの問題がある：
① 各フレームを**高品質に生成する**こと
② フレームを**時系列で一貫させる**こと（急に背景が変わらないようにする）

| 技術 | 動画生成での役割 |
|------|------|
| **GAN** | 各フレームを高品質に生成する。生成器が「偽フレーム」を作り、識別器が「本物のフレームか」を判定して競い合う |
| **VAE** | 動画の特徴を潜在ベクトルに圧縮・復元する。フレーム間の変化をなめらかにする用途にも使われる |
| **RNN** | フレームを**時系列として処理**し、前のフレームの情報を次のフレーム生成に持ち越す。「前の場面との一貫性」を保つのに使われる |

→ GAN・VAEで「各フレームの品質」を担保し、RNNで「フレーム間のつながり」を担保する役割分担

| モデル | 開発元 | 特徴 |
|------|------|------|
| **Sora** | OpenAI（2024年2月発表） | 最長1分間の高品質動画を生成できるモデルとして大きな注目を集めた |
| **Veo 3** | Google DeepMind（2025年5月発表） | 超高精細な映像を生成し、環境音・セリフ等の音声も同時生成できる |

## 2. 生成AIのメリット・デメリット（リスク）

### 主なデメリット・リスク

| リスク | 内容 |
|------|------|
| **プライバシー侵害** | 生成されたコンテンツにプライバシー侵害となる情報が含まれる可能性。入力時に個人情報・センシティブ情報を含めない配慮が必要 |
| **知的財産権侵害** | 生成されたコンテンツが著作権・特許・商標・肖像権などを侵害する可能性。権利関係のチェックが必要 |
| **ディープフェイク** | 下記参照 |

### ディープフェイク
- ディープラーニング・生成AIを利用して**非常にリアルな偽の画像・映像コンテンツ**を作成し、人を故意に騙すことを目的として使用される技術
- 元の映像とは異なる人物の顔を合成したり、既存映像に新たな表情・動きを追加したりすることが容易に可能
- 鑑識能力を超えるほど高品質なフェイク映像が生まれることもあり、**偽情報の拡散**など社会問題を引き起こしている

## 3. RAG（検索拡張生成）

### RAGとは
- **Retrieval-Augmented Generation**（検索拡張生成）の略
- 質問を受けたAIが**まず外部の関連文書を検索で集め**、集めた根拠に基づいてLLMが回答を組み立てる仕組み
- 従来のAIは事前学習のみに依存 → RAGは**最新の外部情報や関連文書を取り込める**ため精度と実務適合性が高い
- 回答に自動的に根拠（出典）が挿入されるため、**ハルシネーション抑制**にも有効

### RAGの処理の流れ（3ステップ）

```
① データの準備・インデックス化
② 質問の解析と検索
③ 回答生成
```

**ステップ①：データの準備・インデックス化**

1. **チャンク分割**
   - 「チャンク」＝検索にひっかかりやすいように文書を小さく分割した単位
   - 段落・見出しなど意味の切れ目で小分けにする
   - チャンクに**メタデータ**（発行日・部門・権限など）を付与
   - ⚠️ 長すぎるとノイズが増える／短すぎると文脈が欠ける → 前後のチャンクに重複（**オーバーラップ**）を持たせて適切な長さに調整
   - 図表・スキャン画像は**OCR（光学文字認識）** でテキスト化して本文と結びつける

2. **ベクトル化（エンベディング）**
   - チャンクをそのままではAIが比較しにくいため、**意味を数字化したベクトル**に変換
   - 似た意味の文書ほど近い座標、違う意味ほど遠い座標に配置
   - **ベクトルデータベース**に保存してインデックス（索引）を作成

**ステップ②：質問の解析と検索**
- 質問も同じ方法でベクトル化し、類似した意味を持つチャンクを高速検索
- メタデータ（発行日・権限）で絞り込み、回答に最適なチャンクだけをLLMに渡す

**ステップ③：回答生成**
- LLMが渡された根拠から一貫した文章を組み立て、**出典を添えて返答**する

> **覚え方：** 「人間が調べてから答える手順をAIで再現するイメージ」

## 4. AIエージェント

### AIエージェントとは
- **状況把握 → 計画 → 行動 → 結果評価** のサイクルを繰り返し、複数タスクを横断して処理するAI
- 単に質問に答えるだけでなく、自ら目標を分解し最適な行動計画を立てて実行する

### 実装の種類

| 種類 | 内容 |
|------|------|
| **ワークフロー型** | 受注処理・請求書発行など、あらかじめ定義した業務フローで確実に処理する |
| **自律型** | LLMがループ（命令群の構成）で最終目標に向けて必要に応じてタスクを再分割・再実行する |

### 主なAIエージェントの特徴

| エージェント | 特徴 |
|------|------|
| **Genspark（ジェンスパーク）** | 調査・立案・画像生成・電話代行などを統合した**オールインワン型スーパーエージェント**。モバイル版あり。ドキュメント生成・意思決定など複合タスクをワークフロー的に束ねながら外部機能を呼び出す |
| **Manus（マナス）** | シンガポール開発の**汎用AIエージェント**。クラウド上でオンライン独立稼働し、人間の操作なしで複雑な業務を遂行。大量の書類分析・Excelへの出力など長時間の事務処理を全自動化する用途に強み |
| **SkyWork AI（スカイワークAI）** | 人間のシンプルな指示から文書・プレゼンスライド・表計算・音声コンテンツなどを同一ワークスペースで作る**ワークスペース型エージェント**。資料作成時間を大幅に短縮 |

## 5. MCP（Model Context Protocol）

- Anthropicが発表した、**LLMと外部ツール・データソースを一つの共通規格でつなぐ仕組み**
- アプリケーション（クライアント）とツール（サーバー）が**共通のプロトコル**でメッセージをやり取りする

### MCPの処理の流れ
```
① 利用可能なツールとスキームの取得
② LLMによるツールの選択とコマンドの生成・送信
③ 結果の受信と回答の提示
```

→ 自然言語の指示から外部APIを実行する
→ Genspark・Manus・SkyWork AIなどは検索・更新等の外部処理を**対話の流れのまま自立的に取り込む**ことができる
