# 第4章：インターネットリテラシー・個人情報・知的財産権

---

## 1. インターネットリテラシーとは

- インターネットに関わるテクノロジーを理解し、適切に使用できる**知識・能力**のこと
- 「リテラシー」＝もとは「読み書き能力」を意味する英語。現在は「特定分野の知識・理解力・能力」という意味で広く使われる

### インターネットリテラシーの主な要素

| 要素 | 内容 |
|------|------|
| **テクノロジーの理解** | 時代の流れに合わせてテクノロジーを把握する能力 |
| **情報リテラシー** | 特定の情報を迅速に見つけ・判断し・活用する能力 |
| **セキュリティとプライバシー** | データのプライバシーを守る手段を知り実践する能力 |
| **デジタル市民権** | 下記参照 |

**デジタル市民権とは（わかりやすく）：**
「インターネット上でも、現実社会と同じように責任ある行動ができる市民としての意識・能力」のこと。
市民権は誤訳だからそのまま考えないように。あくまで行動規範を記載している
具体的には：
- 情報を効果的に見つけ・活用・創造できる
- 他のユーザーやコンテンツに対して**倫理的な視点**で関わる
- 自分の権利を認識しながら、**オンライン環境を安全・責任ある方法で活用**できる

## 2. セキュリティとプライバシー保護

### フィッシング詐欺

**なぜ「フィッシング（Phishing）」という名前？**
英語の「fishing（釣り）」から来ている造語。
「餌（偽のメール・サイト）を使って人をおびき寄せ、個人情報を釣り上げる」という行為を「釣り」に例えた。

- メール・Webサイトを通じて、詐欺師が**正規の機関やサービス提供者を装い**、個人情報・金融情報を不正に収集しようとする詐欺

### QRコード
- 「Quick Response Code」の略。スキャンするだけで関連URLに自動誘導されるコード
- **偽のQRコード**（悪意のあるサイトへ誘導）の場合、詐欺被害につながる可能性がある

### Wi-Fi
- デバイス同士を無線で接続してインターネット・ネットワークにアクセスするための技術・規格
- **偽のWi-Fiに接続すると通信内容を盗聴されるリスクがある**
- 対策：Wi-Fiオフ設定・自動接続しない設定にする
- ⚠️ 自ら判断して接続しても安全とは限らない（偽名を名乗る偽Wi-Fiもあるため）

### アップロード・ダウンロードの危険性

| 操作 | 主なリスク |
|------|------|
| **アップロード時** | 個人情報・機密情報の流出 |
| **ダウンロード時** | **マルウェア**への感染 |

### マルウェア

**「マリシャス（Malicious）」とは？**
英語で「悪意のある・有害な」という意味。
**Malicious Software（悪意のあるソフトウェア）**の略が「マルウェア」。

- **コンピュータ利用者に被害をもたらすことを目的としたソフトウェアの総称**
- 対策：アンチウイルスソフトを最新状態に保つ・ダウンロード前にファイルの出所を確認・未知のソースのファイルを開かない

### ランサムウェア
- マルウェアの中でも特に危険性が高いもの
- 「Ransom（身代金）＋ Software」を合わせた造語
- 感染したコンピュータ内のデータを**無断で暗号化して人質にし**、復元するための身代金を要求する
- ⚠️ 身代金を払ってもデータが復元される保証はなく、さらに高額の要求をされる可能性もある

## 3. ソーシャルエンジニアリング攻撃

- **信頼・恐怖・好奇心**といった人間の心理的・感情的な隙をついて、個人情報や重要データを盗み出す手法

| 手法 | 内容 |
|------|------|
| **スピアフィッシング** | 特定の個人・組織を標的にしたフィッシング攻撃。事前に対象をリサーチし、信頼できる人物になりすましてメール等でリンク・添付ファイルを送信し情報を詐取する |
| **フィッシング** | 不特定多数を対象とした詐欺 |
| **ベイト攻撃** | 「Bait＝餌」から来た言葉。魅力的なソフトウェアや注目コンテンツを「餌」にターゲットの興味を引き、情報を取得したりマルウェアをダウンロードさせる |
| **ブラックメール** | 秘密や情報を公開すると脅迫して金銭を要求する行為（いわゆる「ゆすり・恐喝」） |
| **プリテキスティング** | 下記参照 |

**プリテキスティング（Pretexting）とは？**
「Pretext（口実・でっち上げた理由）」から来た言葉。
**「嘘のシナリオを作り上げて相手を騙し、情報を引き出す」**手法。

例：「システム管理者です。緊急メンテナンスのためパスワードを教えてください」
→ 実際には攻撃者が管理者を装っているだけ。「もっともらしい理由（口実）」を作ってターゲットの信頼を得る。

## 4. プライバシー設定

- 他のユーザーや企業が自分の個人情報にどの程度アクセスできるかを設定すること
- 設定をせずにアプリを利用していると、**知らぬ間にプライベート情報が閲覧・収集される**可能性がある

## 5. 個人情報保護法

### 目的・経緯
- 正式名：**個人情報の保護に関する法律**
- 目的：**個人情報の有用性に配慮しつつ個人の権利・利益を保護すること**

| 年 | 内容 |
|------|------|
| **2005年** | 個人情報保護法の全面施行 |
| **2016年** | 個人情報保護委員会の設置（内閣府の外局） |
| **2017年** | 個人情報取扱事業者の範囲拡大（取り扱う個人情報の数に関わらず、個人情報データベース等を事業用に使用しているものは対象に） |

### 個人情報の定義

生存する個人に関する情報で、次のいずれかに該当するもの：
1. 氏名・生年月日などにより**特定の個人を識別できるもの**（例：住所・電話番号・メールアドレス・防犯カメラの記録等）
2. **個人識別符号**が含まれるもの（例：顔認証・指紋・DNA・マイナンバー・免許番号等）

### 要配慮個人情報 vs 通常の個人情報

**違いをひと言で：**
> 通常の個人情報＝「誰か特定できる情報」
> 要配慮個人情報＝「特定できる＋差別・不利益につながりうる繊細な情報」

| 種類 | 内容 | 扱い |
|------|------|------|
| **通常の個人情報** | 氏名・住所・電話番号・メールアドレスなど | 利用目的の明示・管理が必要 |
| **要配慮個人情報** | 人種・信条・社会的身分・病歴・犯罪歴・犯罪被害事実など | 取得・利用・提供に**事前の本人同意が必要**。漏洩した場合は**個人情報保護委員会への報告が必要** |

**なぜ要配慮か？**
これらの情報は「知られると差別・偏見・不利益を受けるリスクが特に高い」情報。
例：病歴が知られると就職や保険に影響する、犯罪歴が知られると社会的不利益を受けるなど。

### 匿名加工情報

**「結局何なのか」をストーリーで理解：**

```
【問題】
個人情報はそのまま使うと「個人を特定できる」ため、
本人の同意なく企業が分析・公開するとプライバシー侵害になる。

【解決策：匿名加工】
個人を特定できないように加工して「誰のデータか分からない状態」にする。
例：「山田太郎、35歳、東京都、年収600万円」
　→「30代、関東在住、年収500〜700万円台」に変換

【なんのために作るか？】
匿名加工情報にすることで、
・本人の同意なしで第三者提供・分析・活用が可能になる
・企業がデータビジネスや統計分析に活用できる
・一方、元の個人情報に戻せないようにする義務がある（復元禁止）
```

**事業者の主な義務：**
- 元に戻せないよう適切に加工する義務
- 加工方法の安全管理・取り扱い項目の公表義務
- 第三者提供時は「匿名加工情報である旨」を明示する義務

### センシティブ情報（機微情報）

**「要配慮個人情報と何が違うの？」**

| 種類 | 根拠 | 内容 |
|------|------|------|
| **要配慮個人情報** | 個人情報保護法 | 人種・信条・病歴・犯罪歴など（法律上の定義） |
| **センシティブ情報（機微情報）** | 金融分野の個人情報保護ガイドライン | 政治的見解・宗教・労働組合・健康状態・性生活・性的指向・刑事処分の事実なども含む（業界ガイドラインによる広い定義） |

→「センシティブ情報」は金融業界等で使われる概念で、要配慮個人情報より広い範囲をカバーする。
**「特に慎重に扱われるべき個人情報」の総称として覚える。**

### 生成AIと個人情報保護
- 個人情報を含むプロンプトを入力する場合、**利用目的に必要な範囲内**に留めること
- 利用目的を超えて収集した個人情報を利用する場合は**事前に本人の同意**を得ること
- 収集した個人情報は目的外使用や不正な提供を避けること
- 個人情報の保管・廃棄には適切なセキュリティ対策を講じること

## 6. 知的財産権の基本（試験用：表で一気に覚える）

- **知的財産権**＝人間の知的活動で生み出された財産的価値のあるものについて、創作者・発案者に与えられる法的な権利の総称

### 主な知的財産権の種類（試験頻出）

| 権利 | 何を守る？ | 手続き | 存続期間 |
|------|------|------|------|
| **著作権** | 文章・音楽・絵・映像など「表現した作品」 | **不要**（創作した瞬間に自動発生） | 個人：死後70年／法人等：公表後70年 |
| **特許権** | 新しい発明（技術的なアイデア） | **必要** | 出願日から**20年** |
| **意匠権** | 物品・建築物・画像のデザイン（見た目） | **必要** | 出願日から最長**25年** |
| **商標権** | ブランド名・ロゴマーク（識別マーク） | **必要** | 登録日から**10年**（更新可能） |
| **肖像権** | 自分の顔・姿を無断使用されない権利 | **不要** | 明文規定なし。憲法13条が根拠 |
| **パブリシティ権** | 著名人の名前・肖像の経済的価値（肖像権の一部） | **不要** | 判例で保護 |

**覚え方のコツ：**
- 著作権だけが「**登録不要・自動発生**」。他は手続きが必要
- 著作権が「死後70年」と最も長い
- 商標権だけが「**更新で永続できる**」唯一の権利

## 7. AI生成物と知的財産権（「で？」を解消する）

**試験で問われるポイントは「人が創作的に関与したかどうか」が判断基準という点。**

```
【共通の考え方】
人が創作的に関与している → その著作物・発明等は「人のもの」として保護される
人が全く関与していない  → 現行法では「誰のものでもない」＝保護されない可能性

→ 「AIを道具として使った」か「AIが勝手にやった」かが分かれ目
```

### 権利別まとめ

| 権利 | AI生成物の扱い |
|------|------|
| **著作権** | 人の創作意図・創作的行為がある → 著作物に該当し、AI利用者が著作者。ボタンを押すだけ → 著作物に該当しない |
| **特許権** | 人が創作的に関与 → 人の発明として特許取得可能。AI単独の発明 → 現在の日本では特許取得不可 |
| **意匠権** | 特許権と同じ考え方。人の関与があれば人の意匠 |
| **商標権** | 創作よりも「使用」が重視。AI生成の商標でも**人が生み出した商標と同じく保護対象になる** |
| **肖像権** | AI生成画像に実在する人物の顔・姿が含まれる場合、内容によって**肖像権が発生する可能性がある** |
| **パブリシティ権** | AI生成の広告等に著名人の肖像・氏名が使われる場合、商業利用であれば**パブリシティ権が発生する可能性がある** |

## 8. 不正競争防止法

### 目的
事業者間の**公正な競争**を確保し、不正競争を防止するための法律。

### 主な不正競争行為（具体例で理解する）

| 類型 | 一言 | 具体例 |
|------|------|------|
| **著名表示の希釈化行為** | 有名ブランド名を勝手に使う | 「エルメス」という名前の無関係な商品を販売する |
| **周知表示の混同行為** | 有名ブランドに似せて消費者を混乱させる | コカ・コーラそっくりのロゴで別の飲料を販売する |
| **商品形態の模倣行為** | 他社商品の見た目をそっくり真似る | ヒット商品のデザインをコピーして販売する |
| **営業秘密に関わる不正行為** | 企業の秘密情報を盗んで使う・流す | 競合他社が転職者から前職の顧客リストを入手して使用する |
| **限定提供データに関わる不正行為** | 限られた人だけに提供されているデータを不正に取得・使用する | 有料会員のみに提供されているデータを不正取得して利用する |
| **技術的制限手段に関わる不正行為** | コピーガードや認証を不正に突破する | DVDのコピープロテクトを解除するソフトを提供する |

### 営業秘密とは？なぜ3要件を満たす必要があるか？

**「営業秘密」とは何か：**
企業が持つ「外部に知られたくない有用な情報」のこと。
例：顧客リスト・製造ノウハウ・未発表の新製品情報・価格戦略など。

**なぜ3要件が必要か：**
```
「営業秘密」として法律で保護されるには条件が必要。
条件なしで「これは秘密だ！」と主張できてしまうと、
誰でも何でも「うちの秘密」と言い張って競争を妨げることができてしまう。

→ 本当に保護が必要な情報かを判断するための3つの条件（3要件）が設けられている。
```

| 要件 | 内容 | 具体例 |
|------|------|------|
| **秘密管理性** | 「秘密として管理している」ことが客観的に分かる状態であること | アクセス制限・秘密保持契約（NDA）・施錠管理など |
| **有用性** | 事業活動に役立つ技術上または営業上の情報であること | 顧客リスト・製造ノウハウ・価格戦略など |
| **非公知性** | 世間に知られていないこと（公開情報ではないこと） | プレスリリース済みの情報は対象外 |

### 限定提供データとは？なぜ3要件を満たす必要があるか？

**「限定提供データ」とは何か：**
特定の人・企業にだけ提供されるデータのこと。
例：地図データ・気象データ・産業データなど、有料や契約ベースで提供されているデータ。

**なぜ3要件が必要か：**
```
営業秘密と同様に、「保護に値するデータかどうか」を明確にするため。
誰でも普通に入手できるデータを「うちの限定データだ！」とは言えないようにするために3要件がある。
```

| 要件 | 内容 | 具体例 |
|------|------|------|
| **業として提供** | ビジネスとして継続的・反復的に特定の相手に提供していること | 気象会社が会員企業に毎日気象データを提供する |
| **電磁的方法により相当量蓄積** | デジタルで大量に蓄積されており、活用価値がある状態 | 数年分の取引データ・センサーデータなど |
| **電磁的方法により管理** | アクセス権限のある特定の人以外はアクセスできないよう電子的に管理していること | ID/パスワード管理・API認証など |

### AI生成物と不正競争防止法
- 生成AIの生成物でも**3要件を満たせば営業秘密として保護される**
- 他社の**営業秘密を生成AIに入力**し、その生成物を利用することは**不正競争防止法違反となる可能性がある**
- 防止策：生成AIに営業秘密を入力しない／誤って入力した場合はその生成物を利用しない
